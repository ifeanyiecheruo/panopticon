# dbstore

Scaffolds and generates code for a component's private SQL store: schema
migrations (managed by [goose](https://github.com/pressly/goose)) and
type-safe query code (generated by [sqlc](https://sqlc.dev)) from one
`<name>.dbstore.json` project file per store.

Ported from [`../../../morsel/cmd/dbstore`](../../../morsel/cmd/dbstore) —
that project's version is the fuller original; this copy is unchanged except
for import-path-adjacent comments. If a fix belongs here, it probably
belongs there too.

This tool never opens a database connection itself. At runtime, each store's
own `migrate.go` (see [`../../controller/internal/dbstore`](../../controller/internal/dbstore)
for the example) embeds its migrations directory and applies pending
migrations via goose's `Provider.Up()` on every open — `dbstore` only
scaffolds new migration files and drives sqlc codegen ahead of time.

## Project file shape

```json
{
  "engine": "sqlite",
  "src": { "schemas": "schemas/db", "queries": "queries" },
  "gen": { "dst": "queries", "package": "queries" }
}
```

All four paths are relative to the directory the `.dbstore.json` file lives
in.

## Commands

```
dbstore init --project <name>.dbstore.json [--engine sqlite|mysql|postgresql]
    Creates the project file and an initial 001_initial.sql migration stub.

dbstore migrate new <name> --project <name>.dbstore.json
    Scaffolds a new NNN_<name>.sql migration file in the store's schema
    directory (NNN is one more than the highest existing number).

dbstore generate --project <name>.dbstore.json [--project ...]
    Runs sqlc against each project's schema+queries, writing generated Go
    into gen.dst. Multiple --project flags that resolve to the same
    (queries, dst, package) triple are grouped into a single sqlc
    invocation with a combined schema list.
```

## How this repo wires it up

The root `Makefile`'s `generate` target doesn't call `dbstore` directly — it
goes through [`../go-deps`](../go-deps), which turns a `*.gen.json` sidecar
next to a `.dbstore.json` project file into a real Make file-target with
accurate prerequisites (see that tool's own doc comment, and
`controller/internal/dbstore/queries.gen.json` for the actual sidecar).
`make generate` (or just `make build-controller`/`make test-controller`,
which depend on it) is what a contributor actually runs — `dbstore` itself
is an implementation detail of that.

## A note on cross-module `go run`

`queries.gen.json`'s `cmd` invokes this tool as `go run
../../../tools/dbstore ...` from inside `controller/internal/dbstore`. Since
`controller` and `tools/dbstore` are separate Go modules, that only resolves
because of the `go.work` file at the repo root — without it, `go run` refuses
a relative path outside the calling directory's own module ("directory ...
outside main module or its selected dependencies"). See docs/quirks/dev-tooling-windows.md.
